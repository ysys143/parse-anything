# Semantic Captioning Layer — 기능 요구사항 & 역설계 계획

> parse-anything 로드맵 후보 능력. 결정적 구조화 위에 **요소 단위 의미 캡셔닝(OCR + Captioning 융합)**을
> 얹어, 표·도면·차트·폼·약관 같은 고난도 레이아웃에서 "값이 무엇을 뜻하는지"까지 추출하는 계층.
> 본 문서는 관찰된 한 상용 문서 파서(reference implementation)의 기능을 역설계해 정리한 것이다.
> 관찰된 산출물의 오류는 "정상 구현됐다"고 가정하고 기능 목표를 정의하며, 실제 결함은 §5에
> "재현 시 방어할 리스크"로 분리 기재한다. (경쟁 제품 특정 분석·근거 자료는 리포지토리에 커밋하지 않는다.)

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| **한 줄 정의** | 임의 형식 문서를 입력받아 `글자(OCR) + 의미(Captioning)`를 함께 추출하고, 요소 단위 grounding·자연어 해설·구조화 JSON을 산출하는 문서 이해 계층 |
| **핵심 아이디어** | 단일 OCR이 아니라 **두 경로(추출 엔진 + 해설 엔진)의 상호 검수**로 결과를 보완 |
| **1차 산출물** | ① 구조화 데이터(JSON) ② 요소별 자연어 해설(caption) ③ 원본 위 요소 grounding(bbox/마커) |
| **하위 소비자** | RAG 근거 데이터, Agent 입력 (parse-anything의 agent-ready 아티팩트와 정합) |
| **parse-anything 정합** | 결정적 구조·value oracle는 유지, 캡셔닝은 VLM 경로에 위치. 수치는 결정적 추출로 고정하고 서술만 VLM에 위임 |

## 2. 대상 문서 유형

| 유형 | 대표 문서 | 난제 |
|---|---|---|
| 엔지니어링 도면 | 기계 도면, 설비 입면도 | 치수·공차·기호가 선 위에 흩어짐, 기준점(EL 등) |
| 정책/보고서 도식 | 구조도(AS-IS/TO-BE) | 계층·관계 도식 |
| 계약/약관 다이어그램 | 지급 흐름도 | 시간축 + 조건 분기 |
| 폼(인쇄·손글씨) | 신청서/영수증 | 라벨-값 페어, 필기 인식 |
| 통계 인포그래픽 | 통계 보고서 | 막대/점선 혼합, 축·단위·추세 |

## 3. 기능 요구사항 (Functional Requirements)

**FR-1. 멀티포맷 수집** — 이미지/PDF/스캔본을 페이지 단위 처리, 원본 해상도 보존.

**FR-2. 레이아웃·요소 탐지 + Grounding**
- FR-2.1 의미 단위 요소(표·그래프·도식·치수군·폼 필드)를 영역으로 검출.
- FR-2.2 검출 영역에 번호 마커/bbox를 원본 위에 오버레이.
- FR-2.3 각 마커 ↔ 해설 텍스트 매핑(caption grounding).

**FR-3. 이중 인식 경로**
- FR-3.1 추출 엔진(OCR): 인쇄체·손글씨·주석·도장 텍스트.
- FR-3.2 해설 엔진(VLM Captioning): 요소의 의미·관계·추세를 자연어로 서술.
- FR-3.3 두 경로의 상호 검수·보완.

**FR-4. 구조화 출력(JSON)**
- FR-4.1 필드/값/영역좌표/캡션을 기계가독 스키마로 출력.
- FR-4.2 표는 셀 구조(행·열·병합) 보존.
- FR-4.3 폼은 라벨-값 페어로 구조화.

**FR-5. 도메인 의미 추출**
- FR-5.1 도면: 치수(반지름·각도·길이), 기준점, 축척, 대칭/중심선 관계.
- FR-5.2 표제란(title block): 제작자·축척·프로젝트 등 메타데이터.
- FR-5.3 도식: AS-IS/TO-BE 등 구조 비교, 계층·관계.
- FR-5.4 분기 다이어그램: 시간축 + 조건별 결과 로직.
- FR-5.5 차트: 축·계열·단위·수치·추세 + 정량 요약.

**FR-6. 품질 신뢰도** — 요소/문서 단위 신뢰도 스코어 산출·표기, 자동 분석과 원본의 정확도 차이 고지.

**FR-7. 비교 뷰어(UX)** — 좌 원본 / 우 파싱결과 병렬, 마커-캡션 연동.

**FR-8. 하위 연동** — JSON을 RAG 근거로 export, Agent 워크플로 입력 연결.

## 4. 역설계 계획 (Phases)

관찰 가능한 산출물(oracle)로 각 단계 검증.

- **Phase 0** 스펙 동결 & 골든셋 구축 — 도메인별 소수 샘플 + 기대 출력 라벨링.
- **Phase 1** 파이프라인 스켈레톤 — `ingest → layout_detect → ocr → caption → fuse → verify → emit` stub.
- **Phase 2** 레이아웃/요소 탐지 + grounding (FR-2). IoU 검증.
- **Phase 3** OCR 레이어 (FR-3.1). 폼 필드 라벨-값 문자 단위 대조.
- **Phase 4** VLM Captioning (FR-3.2, FR-5). 골든 캡션 엔티티 체크리스트.
- **Phase 5** 융합·상호 검수 (FR-3.3). 값은 OCR, 서술은 VLM. §5-A 훅.
- **Phase 6** 구조화 스키마 & 표 보존 (FR-4). TEDS/스키마 밸리데이션.
- **Phase 7** 신뢰도 스코어링 (FR-6).
- **Phase 8** 비교 뷰어 (FR-7).
- **Phase 9** 평가 하네스 — CER/WER, TEDS, 캡션 엔티티 recall, 단위 정합성.

의존성: Phase 2·3 병렬 → 4 → 5 → 6/7 병렬 → 8. Phase 0·9는 전 구간 관통.

## 5. 재현 시 방어할 리스크 (관찰된 결함 일반화)

관찰된 상용 파서에서 실제로 드러난 결함을 일반 리스크로 정리. (구체 사례·근거는 로컬 teardown 참조.)

| # | 리스크 | 대응 |
|---|---|---|
| A | **수치 단위 정합성 미보증** — 캡션이 축/단위 라벨(예: 천 단위)을 무시하고 raw 숫자만 읽어 스케일 오류 | Phase 5에 단위 정규화 + 캡션 수치의 OCR 원값 교차검증 훅 필수. 값 서술은 VLM이 아닌 결정적 경로로 고정 |
| B | **산술 일관성 부재** — 부분합≠전체 | 합계/부분 관계 정합 체커 규칙 |
| C | **엔티티 변형** — VLM이 고유명사·식별자를 그럴듯하게 재작성 | 고유명사/식별자는 OCR 추출값 그대로 인용, VLM 재생성 금지 |
| D | **문서유형 분류 오류** — 도면을 차트로 오분류 | 명시적 문서유형 분류 단계 + 캡션 템플릿 라우팅 |
| E | **출력 톤/포맷 비정규화** — 캡션 문체가 케이스별 상이 | 말단 출력 정규화(레지스터·용어·수 표기) |
| F | **캡션 신뢰도 < 원본** — 자동 캡션이 원본보다 부정확 | 캡션은 정답 아닌 보조 근거로 취급, RAG 게이팅 + human-in-loop |
| G | **Grounding 정확도 미검증** — bbox↔캡션 오매핑 시 A로 직결 | bbox-caption 매칭 정량 검증 |
| H | **PII** — 폼에서 개인정보 평문 노출 | 마스킹/레드액션 정책, 테스트는 합성 데이터 |
| I | **평가셋 대표성** — cherry-pick 샘플 | 자체 골든셋 난이도·출처 다양성 확보 |
