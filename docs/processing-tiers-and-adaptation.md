# Processing Tiers and Domain Adaptation — Requirements

> 상태: 필수 목표 계약(보완). `pdf-pipeline-requirements.md`가 정의한 파이프라인 메커니즘을,
> **deterministic ↔ VLM ↔ human 3계층 경계 정책**과 **도메인 적응 도구** 관점에서 명시한다.
> 관계: 렌더·추출·표·VLM·가드·출력·검증·라이선스의 *메커니즘*은 `pdf-pipeline-requirements.md`가 규정한다.
> 이 문서는 *계층 간 경계를 어떻게 정하고, 그 경계를 도메인마다 어떻게 적응시키는가*를 규정한다.

## 1. 원칙 (Principles)

- **P1. 3계층.** 처리는 deterministic(결정론), VLM, human 세 계층으로 나뉜다. 각 계층은 역할과 *권위(source of truth)*가 다르며, 계층 간 이동은 *에스컬레이션 결정*이다.
- **P2. 오류율은 도메인/데이터 종속이다.** 보편 임계값은 존재하지 않는다. 처리깊이·가드·에스컬레이션 정책은 *대상 도메인의 실제 문서에서 측정해 보정*해야 한다 (cf. 파이프라인 §3.5, §8).
- **P3. 사람 검증은 환원 불가능하다.** 자동으로 검증할 수 없는/고위험 잔여는 항상 사람의 몫이다. 목표는 사람 노력을 *제거*가 아니라 *최소화·타겟팅*하는 것이다.
- **P4. 따라서 도구가 제품의 일부다.** 시스템은 *도메인 적응(측정 → 사람검증 → 보정)을 쉽게 하는 도구*를 함께 제공해야 한다. 임계값은 코드가 아니라 측정이 정한다.

## 2. 계층 모델과 권위 (Tier Model & Authority)

| 계층 | 권위를 갖는 대상 | 갖지 않는 것 |
| --- | --- | --- |
| **T-DET** 결정론 | born-digital의 값·텍스트·bbox·표영역의 source of truth | 스캔, 의미 설명, 결정론이 놓친 복잡 구조 |
| **T-VLM** | 구조/레이아웃 재구성, 스캔(텍스트 레이어 없음), 의미 설명(그림/차트), 결정론이 놓친 복잡 표 구조 | **값의 권위 아님** — 숫자는 source 매칭 시에만 신뢰 |
| **T-HUM** 사람 | flag된/자동 검증 불가 잔여의 최종 권위 | — |

- **R-T1.** born-digital 문서에서 값(숫자/텍스트)의 권위는 T-DET이다. T-VLM이 낸 값은 결정론 source text와 매칭될 때만 신뢰한다 (cf. 파이프라인 §6).
- **R-T2.** 구조(셀 배치, 병합, 헤더 계층, continuation)의 권위는 결정론이 충분하면 T-DET, 부족하면 T-VLM이다.
- **R-T3.** 자동 검증이 불가능한 잔여(스캔 숫자, 산술 불변식이 없는 표의 구조 오류 등)의 권위는 T-HUM이다.

## 3. 계층 경계 (Escalation)

- **R-B1.** 기본은 *충분한 가장 싼 계층*이다. 트리거가 있을 때만 상위 계층으로 올린다.
- **R-B2. DET → VLM 트리거:** 파이프라인 §3.4의 집합을 따른다 (스캔/텍스트레이어 부재, 그림·차트 의미설명, 인코딩 깨짐·CID 문제, 산술 불변식 실패, 결정론 table/reading-order/bbox 불완전, 저품질·회전·skew).
- **R-B3. VLM → HUM 트리거 (이 문서가 명시):**
  - 가드(source-gate 거부, arithmetic invariant 실패) 통과 못 한 셀
  - 이중 provider pass 불일치 또는 단일 provider 기권
  - 저신뢰 신호(입력 품질 게이트 실패, 저해상도)
  - **산술 불변식이 *없는* 표의 구조 정확성** — universal oracle이 없으므로 도메인 정책상 고위험이면 사람에게
  - 도메인 정책상 고위험 필드(금액, 법적 조항, 식별자 등)
- **R-B4.** 경계는 단일 fuzzy score가 아니라 *결정론 트리거 집합*으로 정한다 (파이프라인 §3.4와 일치).
- **R-B5.** 에스컬레이션 *적극성*은 비용/품질/위험 정책 knob이며, 도메인마다 측정으로 보정한다 (§5).
- **R-B6. 한계의 명시.** 임의의 표/문서 정확성을 자동 보장하는 universal 검증기는 존재하지 않는다. 시스템은 이를 계약으로 인정하고, 잔여를 T-HUM으로 보낸다.

## 4. 계층별 값 무결성 (요약; 상세는 파이프라인 §6)

- **R-V1.** born-digital 값 = T-DET oracle 주입. VLM은 숫자를 새로 읽지 않는다 → 날조 구조적 차단.
- **R-V2.** Source gate(모든 출력 값은 source에 존재) + arithmetic invariant. **arithmetic은 좁은 신호다** — 소계/VAT/수량×단가 같은 계산관계가 있는 표(재무·견적)에만 적용된다.
- **R-V3.** arithmetic이 없는 표(비교표·스펙표·범주표): 값은 source-gate로 안전하지만 *구조*에는 universal oracle이 없다 → T-DET 신뢰 + 결정론 자체 신호(빈 셀/래그드 행/열수 불일치) + 필요 시 T-VLM/T-HUM.
- **R-V4.** 스캔: oracle 없음 → 프롬프트 기권 + 이중패스 + 입력 품질 게이팅, 잔여 위험 셀은 T-HUM.

## 5. 도메인 적응 도구 (핵심 요구)

오류율이 데이터 종속(P2)이고 사람 검증이 필수(P3)이므로, 시스템은 다음 도구를 제공해야 한다.

- **R-A1. (측정)** 도구는 *대상 도메인의 실제 문서*로 파이프라인을 돌려 계층별 산출과 가드 플래그를 생성한다. 보편치가 아니라 *그 도메인의* 오류 특성을 측정한다.
- **R-A2. (리뷰 뷰)** 원본(렌더된 페이지 또는 표 crop)과 추출물(표·값)을 나란히 제시한다.
- **R-A3. (위험 surfacing)** 사람은 전수가 아니라 *플래그된 항목만* 검토한다: source-gate 거부, arithmetic 실패, 이중패스 불일치, 저신뢰, 미검증 구조.
- **R-A4. (판정 캡처)** 사람의 맞음 / 틀림 / 값 교정을 기록한다.
- **R-A5. (골든 부산물)** 판정이 누적되어 *도메인 골든셋*이 된다 — 별도 라벨링 작업이 아니라 리뷰의 부산물로. 파이프라인 §8 코퍼스/스코어카드의 입력이 된다.
- **R-A6. (재실행 비교)** 임계값·프롬프트·경로·provider를 바꿔 재실행하고 오류율·비용·사람검토량을 나란히 비교한다.
- **R-A7. (보정)** 처리깊이·에스컬레이션·가드 정책의 knob은 코드 하드코딩이 아니라 이 측정 결과로 설정·재설정한다 (cf. 파이프라인 §3.5).
- **R-A8. (지표)** 도구는 도메인별로 파이프라인 §8 지표(numeric accuracy, hallucination rate, source-gate false-reject rate, routing/처리깊이 정확도, 비용·지연, guard flag precision/recall, 사람검토량)를 산출한다.
- **R-A9. (프라이버시)** 도구는 민감 문서를 provider I/O 제약(파이프라인 §9)에 따라 처리한다. 민감 문서를 공개 호스팅이 필요한 provider 경로로 보내지 않는다.

## 6. 비목표 / 제약 (Non-Goals)

- **N1.** 보편 오류율을 주장하지 않는다 — 오류율은 도메인 종속이다.
- **N2.** 완전 자동 숫자/구조 정확성을 약속하지 않는다. 잔여는 항상 사람 검토 대상이다.
- **N3.** 사람 검증을 제거하지 않는다. 도구의 목표는 사람 노력의 최소화·타겟팅이다.
- **N4.** 임계값을 도메인 측정 전에 하드코딩하지 않는다.

## 7. 다른 문서와의 관계

- `pdf-pipeline-requirements.md`: 파이프라인 *메커니즘*(렌더·결정론 추출·표 정책·VLM recipe·숫자 가드·출력·검증·라이선스/프라이버시). 이 문서의 DET/VLM/HUM 경계와 도메인 적응 요구사항은 해당 파이프라인의 필수 운영 계약이다.
- 이 문서: 계층 *경계 정책*(DET↔VLM↔HUM)과 *도메인 적응 도구*.
- 측정 근거 후보: pypdfium2 렌더·셀 매핑, pdf-inspector triage 분류, ODL 표 추출, source-gate / arithmetic / 이중패스 / 프롬프트 게이트 / 멀티이미지 / 연속판정 실험 결과. 실제 도메인 오류율은 이 문서 §5의 적응 도구로 다시 측정해야 한다.
