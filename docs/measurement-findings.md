# Measurement Findings (Prototype Evidence)

> 상태: **소표본 프로토타입 증거**. 요구사항 문서(`pdf-pipeline-requirements.md`,
> `processing-tiers-and-adaptation.md`)의 설계 결정을 *뒷받침한 측정*을 기록한다.
> 이것은 코퍼스급 검증이 **아니다** — 파이프라인 §8의 30~50페이지 코퍼스/골든 스코어카드는
> 별도이며(태스크 #14), 여기 결론은 그 측정으로 다시 확인해야 한다.
> 오류율은 도메인 종속이므로(처리계층 P2), 아래 수치는 *이 표본에서의 신호*일 뿐 보편치가 아니다.

## 방법 / 표본

- 도구: `pypdfium2`(렌더·텍스트·char bbox), `pdf-inspector`(triage 분류·표행 검출), `opendataloader-pdf`(ODL: 의미 표 요소·bbox), Gemini direct(VLM), PaddleOCR official API(VLM/OCR).
- 공개 표본:
  - **GeoTopo** (py-pdf/sample-files, 독일어 수학 교재) — 수식·그림·산문.
  - **cardinal / skew** (OCRmyPDF tests, 스캔, 텍스트 레이어 없음) — 2단 브로슈어.
  - **dataeng** (공개 논문 "On Data Engineering…"의 Table 3) — 30행 모델 점수표, `NN.N±N.N` 28개 값이 **검증용 ground truth**.
- 비공개 표본:
  - **한글 서버 견적 PDF**(사용자 Downloads, born-digital, 병합셀 표 + 페이지 걸친 표). 민감 정보이므로 **실제 단가/스펙은 본 문서에 재현하지 않고**, 측정 결과만 추상 기술한다. 이하 "견적표"로 표기.
- 측정 스크립트와 데이터는 git-ignored `.local/`에 보존(`scripts/`, `workspace/`). 비공개 문서 포함이라 커밋 안 됨. 구현 단계에서 검증분만 `prototypes/`로 graduate 예정.

## F1. 렌더러 (→ 파이프라인 §3.1)

- **방법:** PDF 페이지를 PNG로 렌더(pypdfium2, scale 2.0 ≈ 1200×1600px).
- **결과:** GeoTopo/cardinal/scan 정상 렌더. pypdfium2는 BSD/Apache(라이선스 클린). PyMuPDF는 AGPL.
- **결론:** 기본 렌더러 = **pypdfium2**. PyMuPDF 계열은 라이선스 수용 시에만.

## F2. 결정론 레이어 (→ §3.2, 처리계층 R-T)

- **방법:** 같은 표본에 pypdfium2 / pdf-inspector / ODL 비교.
- **결과:**
  - **pypdfium2** — 텍스트+char bbox. 견적표 숫자 셀을 행·열 그리드로 정확 복원(3행×2열). 스캔 판정(텍스트 char 수).
  - **pdf-inspector** — triage 분류 confidence 동반: dataeng/견적표 `text_based` 1.00, cardinal/skew `scanned` 0.95. 표행 검출: dataeng Table 3 = 29행, GeoTopo = 0(산문/수식). **단 견적표 병합셀은 표로 인식 못 함.** MIT, JVM 무.
  - **ODL** — 의미 `table` 요소 + bbox + 행/열 수. 견적 문서에서 표 **4개**를 분리 인식(병합셀 표 포함), pypdfium2/pdf-inspector가 놓친 표까지 잡음. Java 17 동작.
- **결론:** 기본 = **pypdfium2 + pdf-inspector**(라이선스 클린·JVM 무). **병합셀/복잡 표는 ODL**(파이프라인 §2.2). cf. 처리계층 §4.

## F3. 깨끗한 표 숫자 베이스라인 (→ §5, R-V)

- **방법:** dataeng Table 3을 렌더 후 이미지-only로 Gemini·Paddle에 투입, 28개 정답 대비 recall/precision.
- **결과:** **Gemini 28/28, 지어냄 0** · **Paddle 28/28, 지어냄 0** · 두 모델 출력 동일(불일치 0). GeoTopo(수식·그림)·cardinal(2단 스캔)도 Gemini가 읽기순서·그림설명·OCR 양호.
- **운영:** Paddle은 이미지 URL fetch만 지원(base64 미지원) → 호스팅 필요. Gemini는 로컬 바이트. → 민감 문서엔 Gemini/inline 경로(파이프라인 §9).
- **결론:** **깨끗한 born-digital 표에선 두 VLM 모두 수치 할루시네이션 없음.**

## F4. 수치 할루시네이션 — 열화 (→ §6, R-V, R-B3)

- **방법:** dataeng Table 3 이미지를 3단계 열화(축소+블러+저화질 JPEG), Gemini·Paddle recall + precision(지어낸 값) + 이중패스 불일치 측정.
- **결과:**

| 단계 | Gemini recall | Gemini 지어냄 | Paddle | 이중패스 불일치 |
|---|---|---|---|---|
| 원본 | 28/28 | 0 | 28/28, 0 | 0 |
| L1(약) | 26/28 | 2~3 | 27/28 | 5 |
| **L2(중)** | **0/28** | **22+** | 0/28, 0(기권) | 22 |
| L3(강) | 0/28 | 4 | 기권 | 4 |

- **핵심:** L2에서 Gemini가 **존재하지 않는 점수를 자신있게 22개 날조**(전부 `±2.0`, 그럴듯한 범위) — 침묵의 할루시네이션 실재. **실패 모드 비대칭**: Gemini=날조, Paddle=기권(더 안전). 이중패스 불일치가 모든 단계에서 잡힘(실패 모드가 다르기 때문).
- **결론:** 단일 VLM 패스로 열화 입력 숫자 신뢰는 금지. 가드 필요(F5~F7).

## F5. 가드 — 소스 게이트 (→ §6, R-V2)

- **방법:** "출력 숫자가 텍스트 레이어 source에 없으면 플래그"를 F4 출력에 적용.
- **결과:** 원본 35/35 통과·0 오플래그 · L1 진짜 32 통과/가짜 3 플래그 · L2 가짜 30 전부 플래그 · L3 가짜 4 전부 플래그.
- **결론:** **born-digital에선 소스 게이트가 모든 날조(재앙·미묘)를 잡고 0 오거부.** 가장 강한 born-digital 가드.

## F6. 가드 — 프롬프트 (→ R-B3)

- **방법:** L2 열화에 (a) 셀단위 "안 보이면 `[?]`" (b) 전체 "읽을 수 없으면 `IMAGE_TOO_LOW_QUALITY`" 게이트 프롬프트 비교.
- **결과:** (a) 셀단위는 실패(날조 25→20, `[?]` 0개 — 모델이 과신해 자기-플래그 안 함). (b) **전체 가독성 게이트는 L2/L3 날조 0으로 전환**, 깨끗/L1은 정상 전사(오거부 없음).
- **결론:** *재앙적* 날조는 프롬프트 게이트로 차단. *미묘한* 1~2개 오답은 못 막음(결정론 가드 필요).

## F7. 가드 — 산술 불변식 (→ §6, R-V2~V3)

- **방법:** 견적표(소계/VAT/수량×단가)로 per-row 및 교차(VAT=×1.1, 소계=Σ) 불변식 검증.
- **결과:** 모델이 **자기-일관적인 가짜**를 만들 수 있음 — 열화 시 행 내부(`단가×수량=합계`)는 맞지만 값은 전부 틀림. 교차검증(VAT×1.1)은 부분적으로만 잡음(쌍 2개 중 1개 깨짐, 1개는 자기-일관 유지).
- **결론:** **산술은 좁은 신호**(계산관계 있는 표만) + 자기-일관 가짜에 불완전. 독립 가드(소스 게이트)와 겹쳐야 함.

## F8. 값 oracle 주입 (→ R-V1, R-A7)

- **방법:** 견적표를 열화해 Gemini가 숫자를 틀리게 한 뒤, 텍스트 레이어 값을 주입.
- **결과(추상):** 텍스트 레이어 oracle = 12개 값 **12/12 정확, 이미지 열화와 무관**(PDF 텍스트를 읽으므로). 같은 열화 이미지에서 VLM은 12개 중 2개만 맞음. **oracle 주입 후 12/12 복원.**
- **결론:** **born-digital 값은 oracle로 날조 원천 차단**(검증됨). 단 "어느 값→어느 셀" 매핑은 reading-order 데모였고, 프로덕션은 **bbox 앵커링** 필요(구현 과제).

## F9. 크로스-페이지 표 (→ §4)

- **방법:** 견적표(p1→p2 걸침) vs dataeng(p7 Table3 → p8 Table4, 별개 표) 연속판정 + 멀티이미지 재구성.
- **결과:** bbox 열좌표 일치 = **걸친 표 0.77(연속) / 별개 표 0.40(비연속)** — 자동 판별 가능. per-page(둘째장 단독) = 숫자 recall **50%**(반대 장 소실), **멀티이미지(두 장 한 요청) = 100%**.
- **결론:** 걸친 표는 **bbox로 자동 감지 → 멀티이미지 단일 요청**으로 해결(born-digital 숫자 충실도 100%).

## F10. Triage (처리깊이) (→ §3.4, 처리계층 §3)

- **방법:** 신호별 페이지 경로 결정 프로토타입 검증.
- **결과:** scan/born-digital 분리 신뢰(텍스트 char 수 + pdf-inspector). **naive 열-카운팅 표 검출은 과탐**(GeoTopo 산문을 표로). pdf-inspector 표 검출은 격자엔 정확(dataeng 29행)하나 **병합셀 견적표를 놓침**. 이미지 검출로 그림 페이지 분리(GeoTopo 그림 → figure 경로).
- **결론:** 경계는 **결정론 트리거 집합**(퍼지 점수 아님). 병합셀 표 검출은 ODL 필요(F2). born-digital 오라우팅은 텍스트 레이어로 값 보존되어 무해.

## F11. 방향/skew (→ §2.1 재고)

- **방법:** dataeng 표를 90/180/5/10도 회전, Gemini recall + deskew(projection-profile) 측정.
- **결과:** **Gemini 모든 회전에서 28/28 불변.** deskew는 5°/10°를 정확히 추정하나 VLM이 불필요.
- **결론:** **방향 보정은 VLM 품질엔 불필요.** 결정론/bbox 경로(스캔 좌표)에서만 필요. 미검증: skew+저품질 결합.

## F12. 표 구조 충실도 (→ R-V3, R-B6)

- **방법:** dataeng 격자표(정답: 3열·섹션 3·~28행) VLM 구조 vs KMI 병합셀 VLM vs ODL.
- **결과:** 격자표 = **VLM 3열·32행·섹션 3개 정확**. 병합셀 견적표 = **VLM은 1개 표(8열)로 평탄화 vs ODL은 4개 논리 표(9열)로 분리** → 구조 불일치, 정답 라벨 없이 자동 판정 불가.
- **결론:** **값은 oracle로 해결되나 복잡 표 *구조*엔 universal oracle 없음.** 정량 측정(TEDS)은 라벨된 골든 필요(#14), 잔여는 사람(R-B6).

## F13. 복잡 벡터 그림 오라우팅 (실제 코퍼스, → §3.4)

- **방법:** 신경과학 논문(Latimer_kdPCA.pdf) p20 — 다중 패널 플롯(위상도 12개·색상 조건·축라벨) + 그림 캡션 + 본문. 파이프라인에 실투입.
- **결과:** `image_count=0`(벡터 그래픽이라 raster 이미지 객체 없음), `table_rows=4`(플롯 격자·축 눈금이 표로 오인) → **table_vlm으로 오라우팅**. 이러면 oracle 숫자게이트가 *축 눈금 숫자*를 데이터 값으로 취급하는 무의미 검증. `figure_vlm` 경로(이미지 객체 기반)는 안 켜짐.
- **판별 신호:** path 객체 수 — 그림 페이지 **585/270** vs 텍스트 페이지 **5~13**.
- **결론:** triage에 **벡터-그림 탐지**(`vector_paths` + `figure_caption`) 추가, figure-caption AND heavy-path → figure_vlm을 표 규칙보다 우선. 표 오라우팅 방지를 위해 캡션 AND 게이트(본문이 단지 "Fig. 12" 인용 시 path 적어 미발동). 적용 후 Latimer 24p = deterministic 9 / figure_vlm 9 / table_vlm 6.

## F14. 오라클 손검증 — 실코퍼스 + 결함 2종·수정 (→ §3.4, 처리계층 P5/R-A2)

- **방법:** Latimer_kdPCA.pdf의 TABLE_VLM 라우팅 6쪽(p4·8·11·13·15·18)을 Gemini(제품)로 처리한 뒤, **Opus가 사람 위치(검증 오라클)에서 페이지 이미지 vs 제품출력을 손검증** + 값-오라클(텍스트레이어 source-gate) 병행.
- **신호값:**

| p | 실제 | text | paths | img | table |
|---|---|---|---|---|---|
| 4 | 수식 | 2753 | 3 | 0 | 4 |
| 8 | 수식 | 2281 | 7 | 0 | 7 |
| 11 | 그림 | 3000 | 1018 | 0 | 23 |
| 13 | **진짜표** | 2225 | 87 | 0 | 12 |
| 15 | 그림 | 3263 | 928 | 0 | 5 |
| 18 | 그림 | 3907 | 365 | 0 | 5 |

- **결함 A (triage 정밀도 1/6):** TABLE_VLM 6쪽 중 진짜 표는 p13 하나. 5쪽 오라우팅(수식 2 + 그림 3) — pdf-inspector pipe 휴리스틱이 정렬 수식·플롯격자에 과탐. **판별자 = `vector_paths`**(그림 365–1018 ≫ 표 87 ≫ 수식 3–7). `figure_caption` regex는 실제 캡션을 전부 놓침(p11/15/18 모두 False) → **불신뢰, 폐기**.
- **결함 B (프롬프트 환각):** "describe non-text figures in italics"가 그림 있는 **5/5쪽(p20·4·11·15·18)에서 가짜 이탤릭 캡션을 날조**, 그림 없는 쪽(p8·13)엔 0 → 그림 트리거 확정.
- **값-오라클:** born-digital 숫자 p13/15/18 합 **469개 중 날조 0**. 시각 오라클(나)은 fine digit 오독(p13 `2.67±0.52`를 0.53로) → **값-오라클이 권위**. 분업 확증: 구조·환각 = 시각 오라클, born-digital 숫자 = 값-오라클.
- **수정:** (A) `decide_route`를 `vector_paths` 우선(threshold 200, 표 검사보다 먼저), `figure_caption` 폐기 → Latimer 9/9/6 → **10/11/3**(그림 3쪽 교정, 진짜표 p13 유지). 수식→표는 잔존(저위험: born-digital이라 값-오라클로 숫자 보존). (B) `DEFAULT_PROMPT`를 verbatim 전사 + figure는 `[figure]` 플레이스홀더로 → p11 재처리 시 이탤릭 환각 소멸 확인.
- **결론:** 두 결함 다 가드·자기검증으로 **불가**, **오라클 직접 검증으로만** 발견. 오라클이 파이프라인 *바깥* 검증 위치여야 한다는 실증(처리계층 P5).

## F16. 결정론 구조검출기의 문서종속 오탐 (실코퍼스, → 처리계층 P7/§2.6)

- **방법:** pdf-inspector·ODL의 표 *검출*을 CSNL 뇌과학 4편 + HWP 한글 8편에 실투입, 렌더와 대조.
- **결과:** 둘 다 **문서 종류마다 다르게 오탐**.
  - **ODL:** 플롯 페이지에서 축선을 표로 오인 — Latimer p20 = "표" 13개, p21 = 31개(전부 0×0pt·content 0 퇴화 슬리버). 폼 셀의 중첩 하위목록(①②)을 `<br>`로 평탄화.
  - **pdf-inspector:** 목차·산문·차트·수식을 표로 오탐 — IS-200 p3(목차), p11(산문+차트); CSNL 수식·플롯격자.
  - **진짜 표는 양쪽 다 검출** — Latimer p13(0/152 값 정확), IS-200 p18(`<표 5-2>` 괘선표).
- **결론:** **범용 결정론 구조 권위는 없다.** 어떤 단일 검출기도 문서종류 불변으로 옳지 않으므로 **런타임 per-page 자동 라우팅은 오탐 도박** → 폐기, 소스 단위 진단-설정으로 전환(처리계층 P7). 검출기 출력은 *진단 입력(후보)*으로만 쓴다. (F13 벡터그림 신호·F14/F15 연결)

## F17. pypdfium2 vs ODL — 결정론 텍스트/값 다문서 철저 검증 (역할별, → 처리계층 §2.6)

- **방법:** HWP 8 + CSNL 4 전 페이지에서 pypdfium2 텍스트 vs ODL(JSON content) 텍스트를 비교 — 인코딩 깨짐(PUA), 한글 띄어쓰기 비율, 숫자 토큰 커버리지, 헤더/푸터 노이즈. 발산 페이지는 렌더 대조.
- **결과:**
  - **인코딩 깨짐 동등** — KCI에서 양쪽 모두 150 PUA(PDF 자체 문제); CorrectiveFeedback은 py 19 vs ODL 0(ODL이 오히려 깨끗).
  - **한글 띄어쓰기 거의 동등** — 코퍼스 비율 py 0.387 vs ODL 0.382. 폼(양식 p1) py 0.432 vs ODL 0.231은 **최악 이상치**였고, 8문서 중 6문서는 ODL이 약간 더 많음. *한 페이지로 "ODL이 띄어쓰기 망친다"고 일반화한 것은 오류였다.*
  - **청결도: ODL 우위** — ODL이 헤더/푸터를 레이아웃 필터로 제거(IS-200 "IS-200" 보고서번호, 東方學志 헤더). pypdfium2가 더 잡은 숫자 268개(py-only)는 대부분 그 **헤더/푸터 노이즈**.
  - **완전성: pypdfium2 우위** — ODL은 청결을 위해 완전성을 희생: 폼에서 실데이터 "A100 **40**GB"의 40을 누락(pypdfium2엔 있음).
  - **읽기순서:** 코퍼스가 대부분 단일 단이라 발산 없음(둘 다 정확, ODL이 헤더만 제거).
- **결론:** **"pypdfium2가 텍스트로 우수" 가설은 반증 — 일반 우열이 아니라 *역할*이 다르다.**
  - **pypdfium2 = 값·위치 레이어:** 값 *완전성*(안전 오라클은 실숫자 절대 누락 금지) + char bbox(앵커). Java 무.
  - **ODL = 구조·청결 텍스트 레이어:** 표 격자·읽기순서·헤더/푸터 필터. 단 Java 17 필수.
  - 그래서 두 실행 모드 모두 **둘을 함께** 쓴다(처리계층 §2.6, R-M1). ODL 텍스트는 버리지 않되, 값은 pypdfium2 완전성으로 백스톱한다.
