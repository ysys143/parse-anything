01Verdict

Ranking is objective text fidelity against the journal's published full text (whole-document, order-insensitive), cross-checked by a page-by-page vision judge. The top six sit in a tight cluster (0.879–0.890); size did not predict quality.

  1. 1chandra-2 datalab-to · ~4BTop score
    Highest text F1 (0.890) against the published text, with strong number recall (0.892). Emits HTML+bbox layout; occasional invented detail on figures.
  2. 2GLM-OCR zai-org · 0.9BBest overall
    Ties for the objective top (0.887) and for the vision-judge top (5.00) — while being the smallest and fastest model. Clean LaTeX, correct subscripts, right reading order.
  3. 2olmOCR-2-FP8 allenai · 7BCorrected
    Ties GLM objectively (0.887, num_recall 0.892) and is best on the figure page. Against pypdfium2 it had looked worst — a false negative from its YAML front-matter / linearization mismatch, which the published-text score clears.
  4. 4PaddleOCR-VL PaddlePaddle · 0.9BHow you call it
    Its intended layout pipeline (paddleocr doc_parser + vLLM) scores 0.881 with proper LaTeX; the single-shot OCR: call is verbose and LaTeX-free at 0.876. How you call the model matters as much as which model — both go through parse-anything identically.
  5. 4Nemotron-Parse · native nvidia · 0.9BRevived 0.066→0.881
    Session 2: not a bad model — vLLM served this enc-dec VLM image-blind (different pages gave identical hallucinated tables). Native transformers reads each page: 0.881 (ties the pipeline for 4th), num_halluc 0.979→0.247. Top on objective text — but last on the vision judge (3.25): it drops figures/equations as bare picture boxes.
  6. 6DeepSeek-OCR deepseek-ai · 3BClean equations
    0.879 with flawless equations and low hallucination among the leaders. Slightly sparse on the figure page and a few truncations; grounding tokens preserved.
  7. 7Nanonets-OCR2 nanonets · 3.75BHigh ceiling, unstable
    0.875, and strong on the vision judge (4.75) when it behaves — but degenerates into a repeating "!" loop on some pages. Great or broken, per page.
  8. 8Unlimited-OCR · per-page baidu · 3.3BNow deploys
    Session 2: the original "startup exit" was the GENERIC vLLM image — Baidu's OFFICIAL unlimited-ocr-cu129 image works. Per-page 0.809 (prompt must start with <image>). Its native whole-doc mode is measured separately below.

Why not pypdfium2? An earlier version scored against pypdfium2's text extraction — itself a lossy, reading-order-scrambling step, so it measured "similarity to pypdfium2", not accuracy. S2Session 2 · two revivals + the parse-anything pair

The two "failures" above were OUR misconfigurations, not the models — and the ground truth was in the model code, not the card. We also asked: does an end-to-end whole-document model nullify parse-anything, or pair with it?

Nemotron-Parse · 0.066 → 0.881

vLLM served it image-BLIND

Pages 10/20/30 gave byte-similar hallucinated **100.05** tables — the image never reached the ViT-H encoder (vLLM's enc-dec multimodal path breaks here; L4 is not on NVIDIA's validated list). The repetition-stop logits processor treated a symptom. Native transformers (AutoProcessor → generate) reads each page; num_halluc 0.979→0.247.

Unlimited-OCR · now deploys

official image + <image> prompt

The generic vllm-openai image exits at startup; Baidu's official unlimited-ocr-cu129 image works. The prompt must start with <image> (else empty output), and max-model-len 16384 (8192 left no room for the ~3.5k image tokens). Per-page 0.809.

The pair wins, and whole-doc did not nullify it. Wrapping the per-page transcription in parse-anything's deterministic substrate raised token_f1 0.809 → 0.830 and cut num_halluc 0.698 → 0.591 (the value oracle strips grounded-bbox coordinate noise / unsourced numbers). The model's native whole-doc mode broke — it looped after ~1 page at image_size=640 (an eager-memory compromise; flash-attn has no torch2.10 wheel), so whole-doc raw is 0.092 and the whole-doc __pa row (0.716) is really the deterministic ODL floor, which the per-page pair beats by +0.114. Nemotron native (0.881) is already clean markdown, so parse-anything neither helped nor hurt it (0.880). Lesson: model cards give happy-path recipes; the truth — the <image> requirement, the tuple return, the correct logits-processor class name, the vLLM blindness — was only in the model source + empirical testing.

03Vision judge

Claude scored each transcription 0–5 against the actual page image, on four representative pages: a dense body page, a figure page, and two equation-heavy pages. GT-free, so it cross-checks the objective ranking — catching what token overlap can't: LaTeX fidelity, figure handling, and repetition collapse. Re-judged directly (not by a proxy model) and consistently across all eight models in Session 2.

04What actually happened on the L4

Deployment was most of the work. Every model needed a different serving fix; the notes below are the ones that mattered.

GLM-OCR · Nanonets · DeepSeek · chandra

vLLM · OpenAI /v1

Served on vllm-openai. Nanonets gave pure "!" garbage on :latest (a Qwen2.5-VL regression) and had to be pinned to v0.11.2. DeepSeek 400'd until max_tokens fit its 8k context.

olmOCR-2-FP8

vLLM · FP8 on Ada

FP8 weights run natively on the L4 (sm89). Works out of the box on v0.11.2; top-tier text F1 once scored against the published text rather than pypdfium2.

PaddleOCR-VL

vLLM · trust_remote_code

Run two ways: single-shot on vLLM's element-level endpoint, and the official paddleocr doc_parser layout pipeline (backend vllm-server, served name PaddleOCR-VL-1.6-0.9B, needs libgl1). The pipeline gives proper LaTeX and edges the single-shot call. Cross-checked against Baidu's hosted PaddleOCR-VL API (aistudio): byte-similar to the self-hosted pipeline — same doc_parser, figure page handled cleanly, no loop. The single-shot figure-page collapse is a single-shot artifact, not the model.

Nemotron-Parse-v1.2

native transformers (Session 2)

vLLM serves this ViT-H+mBart enc-dec VLM image-blind — swapped to native AutoProcessor → model.generate, which feeds the image to the encoder correctly. 0.066 → 0.881. The card's vLLM recipe and "repetition" caveat both pointed the wrong way.

Unlimited-OCR

official vLLM + native whole-doc (Session 2)

Per-page on Baidu's official unlimited-ocr-cu129 image (the generic image was the "startup exit"), prompt starting with <image>. Whole-doc uses native infer_multi (vLLM can't do multi-page); ran at image_size=640 because eager OOMs the L4 at 1024 and flash-attn has no torch2.10 wheel.

PP-OCRv6-det · nemotron-ocr-v2

excluded / swapped

Detection-only models (boxes, not text) — out of scope for a transcription comparison. Nemotron-Parse-v1.2 stood in for the NVIDIA slot.

05How it was measured

  • Integration. parse-anything's --primary paddle transcriber speaks a 3-endpoint PaddleOCR jobs API. A shim mimics it and routes each page to whichever model is up — zero changes to parse-anything for the per-page sweep (the §S2 whole-doc pair adds a new --whole-doc path).
  • Throughput. Naïve one-page-at-a-time serving is batch=1 and starves the GPU. A pre-transcription pass fires all 46 pages concurrently so vLLM continuous-batches them, then parse-anything replays from cache — ~5× faster (GLM born: 393s → 71s).
  • Documents. A 46-page PLOS Biology paper, born-digital, plus an image-only rasterization (text layer stripped) to force unaided OCR. Scored against the journal's published full text (PLOS JATS XML), not the born text layer.
  • Caveats. Single document, single domain — read the objective scores as relative to this paper, not a general OCR benchmark. The earlier pypdfium2-based char-similarity metric is deprecated (it distorted the ranking). The vision judge (§03) was re-scored directly by Claude on one consistent scale across all eight models. Unlimited-OCR's whole-doc mode ran at reduced resolution (image_size=640) and is not yet fairly measured (§S2).
